# 续言 Continuum

> 让故事接续、延续下去 —— 面向中文网络文学作家的开源写作助手

**续言 / Continuum** 是一款对标并超越「阅文作家助手」的改进型开源写作程序。它以成熟可运行的桌面应用为基础迭代演进，聚焦于为作家群体提供更高效、更贴合真实创作流程的写作辅助能力。

- 打破积分收费壁垒：AI 能力使用你自己的 API Key，成本极低
- 打破模型固定壁垒：支持任意 OpenAI 兼容接口的模型
- 打破平台锁定壁垒：数据本地存储，不依附任何平台
- 开源开放：MIT 协议，可自行二次开发与扩展

> **备选品牌名：落墨 / Luomo** —— “笔落成墨”，寓意所有创作想法从下笔落墨开始。

## 项目简介

网络文学作家长期面临卡文、大纲崩坏、伏笔失控、人设崩塌、更新压力与平台锁定等结构性痛点。现有平台官方工具（阅文作家助手、番茄作家助手等）将创作数据绑定在单一平台生态内，AI 能力以积分/订阅方式收费且模型不可选；通用写作软件（Word、Scrivener、Obsidian 等）又缺乏针对网络文学的创作管理能力。

**续言 / Continuum** 选择第三条路：

1. **以本地桌面应用承载全部创作数据**，作品永远属于作者自己；
2. **以统一的 AI 适配层接入任意 OpenAI 兼容模型**，写作辅助能力由用户自备的 API Key 驱动；
3. **以迭代方式从成熟代码演进**，不依赖任何处于快速迭代期的第三方框架，保证长期稳定可维护。

“续言”二字承载项目的核心意象：**让故事接续、延续下去** —— 无论日更、完本，还是从草稿到终稿，创作从不中断。

## 核心功能

### 当前已具备（基于现有代码）

| 功能 | 说明 |
| --- | --- |
| AI 润色 | 接入 AI 服务对流式返回的润色结果进行处理，支持一键增强文本表达 |
| 全局热键 | 注册全局快捷键，随时唤起创作辅助动作 |
| 剪贴板监听 | 自动监听并加载剪贴板内容，减少复制粘贴的打断 |
| 跨窗口文本录入 | 将文本通过模拟输入写入目标创作窗口，支持快/慢两种录入节奏 |
| 字数统计 | 实时统计文本字数，支持创作目标跟踪 |
| 配置管理 | 可视化配置 AI 服务凭证，配置校验与本地持久化 |
| 日志系统 | 全链路操作日志，便于问题定位与排障 |

### 规划中（详见路线图）

- 作品 / 章节 / 大纲管理（多本书并行创作）
- 写作场景 AI 对话（续写 / 改写 / 扩写 / 缩写 / 润色 / 剧情推演）
- AI 知识库（RAG：角色卡、世界观、伏笔、灵感素材的语义检索）
- AI 朗读（多引擎 TTS，支持角色配音与语速调节）
- AI 文生图（角色形象图、场景概念图）
- 素材库与历史版本管理、多格式导出

## 与同类工具的差异

| 维度 | 阅文/番茄作家助手 | 通用写作软件 | 续言 Continuum |
| --- | --- | --- | --- |
| AI 费用 | 积分/订阅收费 | 无 AI 能力 | 自备 API Key，几分钱/次 |
| AI 模型 | 固定不可选 | — | 任意 OpenAI 兼容模型（OpenAI / DeepSeek / Claude / 硅基流动 / Ollama 等） |
| 数据存储 | 平台云端 | 本地（多为闭源格式） | 本地文件，纯自主可控 |
| 平台绑定 | 必须发布到本平台 | 无 | 导出自由，无平台锁定 |
| 创作管理 | 依赖平台 | 长篇管理能力弱 | 作品/章节/大纲/角色/伏笔一体化 |
| 可扩展性 | 闭源 | 闭源 | MIT 开源，可自由二次开发 |
| 学习成本 | 低 | 中高 | 轻量、贴近网文创作习惯 |

## 快速开始

### 环境要求

- Windows / macOS / Linux
- Python 3.9 及以上（建议 3.10+）

### 安装

```bash
# 1. 克隆仓库
git clone https://github.com/your-org/continuum.git
cd continuum

# 2. 安装依赖
pip install -r requirements.txt
```

### 运行

```bash
# 方式一：命令行启动
python run.py

# 方式二：模块方式启动
python -m continuum

# 方式三：双击 Windows 启动脚本
start_writing_assistant.bat
```

### 运行测试

```bash
python -m unittest discover -s tests -v
```

### 配置 AI 服务

1. 启动应用后点击主界面「Coze配置」（或按版本进入设置）；
2. 填入你的 API 令牌与用户 ID；
3. 应用会自动校验配置有效性并本地保存。

> 规划中的统一 AI 适配层将支持在「设置」中直接选择与配置任意 OpenAI 兼容接口（密钥、Base URL、模型名）。

### 基础使用

- 在文本区输入/粘贴内容，或勾选「自动加载剪贴板内容」；
- 点击「开始转写」将文本写入目标创作窗口（默认目标窗口标题为“作家助手”，可在配置中修改）；
- 点击「润色转写」先调用 AI 润色，再写入目标窗口；
- 全局热键 `Ctrl+G` 可快速触发录入动作。

## 技术栈

| 层 | 技术 | 说明 |
| --- | --- | --- |
| 语言 | Python 3.9+ | 成熟稳定、生态丰富、跨平台 |
| GUI | PySide6（Qt 6） | 原生 Qt 控件 + QSS 主题，成熟稳定、跨平台 |
| 全局热键 | pynput | 键盘监听与全局快捷键 |
| 窗口控制 | pygetwindow | 目标窗口定位与激活 |
| 剪贴板 | pyperclip | 剪贴板读写 |
| 网络/AI | requests | AI 服务流式调用与配置校验 |
| 配置 | JSON + 自研 Config 管理 | 外置配置、本地持久化 |
| 日志 | logging | 文件 + 控制台双通道 |

**规划演进方向**：统一 AI 适配层（OpenAI 兼容协议）、SQLite 数据存储、本地向量检索（RAG）、TTS 引擎适配、Web 级 Markdown 编辑器（QWebEngineView 内嵌）、打包分发（PyInstaller / Nuitka）。

## 项目结构

```
Continuum/
├── run.py                          # 启动入口脚本
├── start_writing_assistant.bat     # Windows 一键启动
├── requirements.txt                # 依赖清单
├── LICENSE                         # MIT 许可证
├── config/
│   ├── coze_config.json            # AI 服务配置（本地保存，不入库）

├── tests/                          # 单元测试（unittest）

    ├── config/                     # 基础设置与 AI 配置管理
    ├── core/                       # 核心服务层（AI、热键、录入）
    ├── gui/                        # 界面层（主窗口、组件）
    └── utils/                      # 工具（剪贴板、随机生成）
```

## 贡献指南

欢迎所有形式的贡献 —— 无论是代码、文档、Issue 反馈，还是使用建议。

### 提交流程

1. Fork 本仓库并创建你的特性分支：`git checkout -b feature/xxx`
2. 提交改动，并保证提交信息清晰：`git commit -m "feat: xxx"`
3. 推送分支并创建 Pull Request：`git push origin feature/xxx`
4. 等待 Review 与合并

### 开发约定

- 新增功能请同步补充/更新对应的单元测试；
- 代码保持 Python 官方风格（PEP 8），关键逻辑添加中文注释；
- 涉及配置项变更时，同步更新 `config/` 下的配置模板与文档；
- 涉及 UI 变更时，在 PR 描述中附上改动说明。

### Issue 规范

- Bug 报告：描述复现步骤、期望行为、实际行为、运行环境；
- 功能建议：说明使用场景、期望效果、可选的实现思路。
