# 续言 Continuum

> 让故事接续、延续下去 —— 面向中文网络文学创作者的开源桌面写作工具

![License](https://img.shields.io/badge/license-MIT-blue.svg)

**续言 / Continuum** 是一款开源的中文网络文学写作工具。它把创作数据完整保存在本地，通过统一的 AI 适配层接入任意 OpenAI 兼容模型，希望帮助长篇连载的作者更好地组织故事、延续创作。

我们并不打算替代任何现有写作产品，而是想围绕「**数据属于作者自己、AI 能力可自由组合、创作过程尽量少被打断**」这三个朴素的原则，做一个顺手的本地写作伙伴。项目仍处于早期迭代阶段（v0.1.0），欢迎试用与反馈。

- **数据自主**：作品与正文以纯 Markdown 保存在本地，随时可用任意文本编辑器打开，无平台锁定
- **AI 自备**：使用你自己的 API Key 直连任意 OpenAI 兼容服务（DeepSeek / OpenAI / 硅基流动 / Ollama），成本透明可控
- **创作友好**：Tiptap 所见即所得编辑器 + 大纲/章纲/思维导图规划 + 伏笔与时间线联动，贴合长篇创作流程
- **知识增强**：本地 BM25 + 可选 Embedding 的混合语义检索，AI 对话自动注入作品知识上下文
- **开源开放**：MIT 协议，可自由使用、修改与二次开发

## 功能特性

### ✍️ 编辑器

- **所见即所得**：基于 Tiptap（ProseMirror）的块级编辑器，原生支持标题、表格、任务列表、代码块、引用、图片、链接等；三种模式（编辑 / 预览 / 源码）一键切换，编辑区即 Markdown 实时渲染
- **格式工具栏**：加粗 / 斜体 / 下划线 / 删除线 / H1–H3 / 引用 / 列表 / 任务列表 / 表格 / 链接 / 图片 / 代码块 / 分隔线 / 撤销重做
- **纸稿排版**：思源宋体衬线正文、行距 1.9、首行缩进，贴近中文阅读习惯；字号、行距、首行缩进、打字机模式等可在格式设置中调整并持久化
- **实时统计与自动保存**：实时中文字数；输入防抖 800ms 自动保存，Ctrl+S 立即落盘
- **章节标题块**：打开章节自动插入章节标题块（可编辑），重命名章节时自动同步
- **查找 / 替换**：Ctrl+F / Ctrl+H 浮窗，支持替换与全部替换
- **伏笔 / 时间标注联动**：选中文本即可「创建伏笔」；正文高亮标注（伏笔状态色 / 时间线紫色），点击标注双向定位侧栏对应条目（收起态自动展开），状态变更后标注颜色即时同步

### 🧭 大纲与规划

- **大纲工作台**：侧边栏「大纲」Tab 常驻入口，中央模式在「写作 ⇄ 大纲」间切换；三视图（大纲列表 / 章纲 / 思维导图）+ 粒度切换（仅核心节点 / 完整细纲）
- **大纲节点**：节奏标签（开篇/发展/高潮/转折/低谷/伏笔/结局）、预估字数、关联章节（点击跳转）、涉及角色（关联角色卡）；拖拽排序，双击重命名
- **章纲管理**：每章一条（核心剧情 / 角色互动场景 / 关键冲突点 / 章末钩子 / 备注 / 写作状态），内联自动保存
- **思维导图**：零依赖 SVG 树状图（缩放 / 平移 / 增删改节点），三种模板（剧情线 / 人物关系 / 世界观），与大纲双向生成，支持 XMind 大纲文本导入
- **智能章纲提取**（AI「提取」）：支持当前章节 / 最近 20 章 / 自定义范围（≤50 章），主进程排队逐章提取，结果写入章纲；受每日 AI 配额约束
- **大纲挂载智能问答**（AI「对话」）：引用大纲节点 / 章纲 / 章节正文作为上下文，针对故事结构答疑

### 📚 创作管理

- **作品 / 章节树**：多作品并行，搜索过滤、双击重命名、一键删除
- **卷层级管理**：作品 → 卷 → 章节三级结构，卷支持新增 / 重命名 / 删除 / 排序，章节一键归属卷（单归属约束），未分卷分组可自定义命名
- **创作知识库**：侧栏 角色 / 设定 / 伏笔 / 素材 四 Tab，结构化记录人物卡、世界观、剧情伏笔与灵感素材，全部纳入语义检索范围
- **时间线模块**：侧栏「时间线」Tab 记录剧情时间节点（可编辑时间 + 剧情梗概），增删改 / 排序 / 实时保存，正文时间标注与条目双向联动
- **全局全文搜索**：Ctrl+Shift+F 跨全部作品检索章节正文与创作知识，结果一键跳转
- **历史版本管理**：Ctrl+S 手动保存自动生成章节快照（每章保留 50 份），可预览与恢复
- **欢迎页与新建向导**：无作品时提供「新建 / 导入 / 示例」入口；新建作品向导支持题材、篇幅、每日目标字数、默认卷名等

### 🏠 首页（作品展览 + 数据统计）

- **作品展览**：启动即进入书架首页，作品卡片化展示（渐变封面题词 / 标题 / 题材 / 简介摘要 / 创建时间）；关键词搜索 + 题材分类筛选 + 分页加载；PC 悬停上浮动效、触屏按压缩放反馈；点击卡片一键进入作品详情（编辑器）
- **数据统计**：作品总数 / 累计总字数 / 今日字数（含每日目标进度）/ 周期字数四张指标卡，数字滚动平滑过渡；周 / 月 / 年维度切换的写作量柱状图，hover 数值浮层、周期切换生长动效、数据更新平滑过渡（每日字数自动记录于本地，跨天连续累计）

### 📥 导入 / 导出

- **Markdown 导入**：作为新作品（+ 第一章）或追加为当前作品的新章节
- **导出**：章节 ×（Markdown / TXT）；作品 ×（Markdown / TXT / **PDF** / **EPUB** / **DOCX**）——PDF 经 printToPDF 排版，EPUB3 标准结构，DOCX 支持标题/列表层级
- **存储引擎**：默认 JSON + Markdown 文件存储；设置环境变量 `CONTINUUM_STORAGE=sqlite` 可切换 SQLite（sql.js 零原生依赖）引擎，接口一致、数据无缝替换
- **插件机制**：启动时扫描 `data/plugins/*.js`，插件可携带元数据与 `onStart` 钩子，加载失败仅告警不阻断

### 🤖 AI 助手

- **统一适配层**：内置预设之外可自定义服务商；兼容 **OpenAI / Anthropic / Coze（扣子）** 三种接口格式自动切换（`/chat/completions` · `/v1/messages` · `/v3/chat`），三段式配置（API Key / Base URL / 模型）+ 温度调节 + 连接校验 + 可选 Embedding 模型
- **流式对话**：AI 面板支持对话 / 润色 / 续写 / 知识库等场景，可「附带上文」（当前章节）与「注入知识库」（RAG 参考片段）让回答贴合语境，默认开启
- **选区工具**：选中正文浮出悬浮操作条（润色 / 改写 / 翻译 / 总结 / 续写），结果在对比浮窗（原文 vs 结果）中确认后一键写回正文（Ctrl+R / Ctrl+J / Ctrl+Shift+T / Ctrl+Enter）
- **透明 AI**：每次请求显示已注入的上下文来源（如「当前章节 + 角色卡 ×2」），让作者清楚 AI 基于哪些材料作答
- **语义检索**：本地 BM25（中文 n-gram）离线可用；配置 Embedding 模型后自动升级为 BM25 + 向量 50/50 加权融合，失败自动降级
- **配额管理**：AI 功能共享每日配额账本（默认 100 次/天，跨天自动重置），用量清晰可控

### 🎨 体验与辅助

- **五套主题**：浅色 / 深色 / 护眼浅（米黄纸稿）/ 护眼深 / 高对比，Ctrl+Alt+T 循环切换并持久化
- **命令面板**（Ctrl+K）：聚合常用动作的模糊搜索面板，最近使用置顶
- **通知中心 / Toast**：全局轻提示 + 铃铛通知历史（Ctrl+Shift+N）
- **沉浸模式**（F11）：隐藏一切干扰，专注写作；悬浮工具条保留退出 / 主题 / 字数 / 目标进度
- **窗口状态持久化**：窗口几何、主题、折叠状态重启后恢复
- **辅助工具**：全局热键 Ctrl+G 唤起窗口、跨窗口文本录入（快/慢节奏）、剪贴板监听与历史一键插入、窗口置顶
- **新手引导（FTUE）**：首次启动三步引导（建作品 → 写作 → AI 润色），可跳过并持久化

## 快速开始

### 环境要求

- Node.js ≥ 18
- npm ≥ 9

### 安装与运行

```bash
# 克隆仓库
git clone https://github.com/RuanCH0924/continuum.git
cd continuum/desktop

# 安装依赖
npm install

# 启动开发模式（Electron + HMR）
npm run dev
```

**Windows 用户**：也可以直接双击根目录的 [`start_continuum.bat`](./start_continuum.bat) 一键启动（自动检测 Node.js、首次自动安装依赖）。

> 国内网络环境如果安装 Electron 二进制超时，可配置 npm 镜像后重试：`npm config set registry https://registry.npmmirror.com`。

### 验证

```bash
npm run typecheck   # TypeScript 类型检查（主进程 + 渲染进程）
npm test            # Vitest 单元测试（242 项 / 29 个测试文件，全量通过）
npm run build       # 生产构建（out/ 产物）
```

> 测试覆盖：存储 CRUD（文件/SQLite）、Markdown 往返、大纲与思维导图解析、AI 流式客户端、快捷键与主题、跨窗口录入核心、写作统计、导入导出、BM25 检索、知识注入上下文、UI 组件交互、首页模块（作品展览筛选/分页/跳转 + 数据统计趋势聚合）。详细报告见 [docs/项目设计文档.md](./docs/项目设计文档.md#8-测试与验证报告)。

## AI 服务配置

1. 点击顶栏「设置」或 AI 面板齿轮，打开 **AI 服务设置**；
2. 选择服务商预设（DeepSeek / OpenAI / Anthropic / Coze / MiniMax / Kimi / 通义千问 / 智谱 GLM / 零一万物 / 硅基流动 / Ollama），预设之外可选「**自定义服务商**」自由接入任意服务（如本地网关等）；
3. 选择**接口格式**：OpenAI 兼容（默认）/ Anthropic / Coze（扣子）——Anthropic 走 `/v1/messages`（`x-api-key` + `anthropic-version`），Coze 走 `/v3/chat`（模型字段填 Bot ID、Key 填个人访问令牌 PAT）；
4. 填入你的 API Key（Ollama 等本地服务无需 Key），选择模型并调节温度；
5. （可选）填写 **Embedding 模型**（如 `bge-large-zh` / `text-embedding-ada-002`）启用知识库语义增强，留空则知识库仅关键词检索；
6. 点击「校验连接」确认配置可用后保存（配置仅保存在本地 `data/settings.json`）。

> AI 对话勾选「注入知识库」后，每次提问会自动检索当前作品的正文与创作知识，
> 以参考片段形式注入提示词（检索失败自动跳过，不影响对话）；AI 用量受每日配额约束。

## 数据存储

所有数据保存在 `desktop/data/` 目录，正文为**纯 Markdown**，可直接用任意文本编辑器打开：

```
data/
├── settings.json                     # 全局设置（主题 / AI 配置 / 统计 / 每日目标 / AI 配额）
├── plugins/                          # 可选插件目录（*.js）
└── works/
    └── <workId>/
        ├── meta.json                 # 作品元数据
        ├── notes.json                # 创作知识（角色 / 设定 / 伏笔 / 素材）
        ├── volumes.json              # 卷容器（章节层级分组，含章节关联）
        ├── timeline.json             # 时间线条目（时间描述 + 剧情梗概）
        ├── outline.json              # 大纲节点（节奏标签 / 预估字数 / 涉及角色）
        ├── chapter_outlines.json     # 章纲（逐章细纲）
        ├── mindmap.json              # 思维导图数据
        ├── embeddings.json           # Embedding 向量缓存（可删除，自动重建）
        ├── versions/                 # 历史版本快照（每章 ≤ 50 份）
        │   ├── index.json            # 快照索引
        │   └── <seq>/<ts>.md         # 快照正文
        └── chapters/
            ├── index.json            # 章节标题索引
            └── 001_章节名.md          # 章节正文（纯 Markdown）
```

> 设置环境变量 `CONTINUUM_STORAGE=sqlite` 后，索引类数据（作品 / 章节 / 卷 / 时间线 / 大纲 / 章纲 / 导图 / 知识）改存 `data/continuum.db`，正文与版本快照仍为 Markdown 文件，接口与目录结构保持一致。

## 技术栈

| 层    | 技术                                                 |

├── LICENSE                   # MIT 许可证

## 路线图

**已完成（M0–M7）**：应用骨架 → 数据层 → 编辑器 → 创作管理 → AI 助手 → 体验层 → 辅助能力 → 验收。

**验收后增量**：数据化收口、导入/导出、创作知识数据模型、RAG 混合语义检索、AI 对话知识注入、交互增强（选区悬浮条 / 对比浮窗 / 改写·翻译 / 新建向导 / 格式设置 / 查找替换 / 面包屑 / FTUE 等）、全局全文搜索、历史版本管理、多格式导出（PDF/EPUB/DOCX）、插件机制、SQLite 存储引擎、卷层级 / 时间线 / 伏笔联动、大纲模块（2026-08-16 第八轮）。

**暂缓（开发完成后再做）**：

- electron-builder 打包分发（Windows / macOS）
- 大纲模板中心、结构化角色卡细化等 P2 规划（详见设计文档 §12）

## 贡献指南

欢迎任何形式的贡献 —— 代码、文档、Issue 反馈或使用建议。

1. Fork 本仓库并创建特性分支：`git checkout -b feature/xxx`
2. 提交清晰的信息：`git commit -m "feat: xxx"`
3. 推送并创建 Pull Request
4. 新功能请同步补充单元测试（Vitest）

Issue 规范：Bug 报告请描述复现步骤、期望行为与实际行为；功能建议请说明使用场景与期望效果。
