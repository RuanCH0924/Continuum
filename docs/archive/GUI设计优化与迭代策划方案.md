## 一、对标分析：腾讯写作助手界面核心优势梳理

腾讯写作助手（参考附件截图）是国内成熟度最高的网文写作工具之一，其桌面端界面在「创作沉浸感 · 信息密度 · 导航效率」三者之间形成了良好的平衡。本节按模块拆解其设计语言，提炼本项目可复用的设计资产。

### 1.1 编辑器布局与信息架构

| 维度 | 腾讯写作助手做法 | 价值点 |
| --- | --- | --- |
| **三栏式总骨架** | 左侧「作品 · 章节 · 大纲」导航 + 中央编辑/预览 + 右侧 AI 助手 | 创作主体居中，导航与辅助信息分列两侧，符合「主体突出、辅助收敛」的视觉重心原则 |
| **中央双栏可切换** | 支持「仅编辑 / 双栏 / 仅预览」三态切换 | 适配「沉浸模式」与「校对模式」两种写作场景 |
| **章节标题与正文分层** | 编辑区上方显示当前章节标题，正文区使用大号宋楷类衬线字体模拟纸稿 | 强化「纸笔感」沉浸体验，减少数字 UI 的违和感 |
| **字数统计内嵌状态栏** | 字数 / 字符 / 当前模型 / 自动保存时间 等信息一目了然 | 让作者在不离开编辑区的前提下感知「进度 · 状态 · 资源」 |
| **顶部极简菜单** | 仅保留「新建 · 导入 · 导出 · 设置 · 帮助」等高频入口 | 顶部菜单不抢戏，把视觉权重让给编辑区 |

**对 Continuum 的启发**：当前主窗口（[app.py](file:///d:/SynologyDrive1/Continuum/continuum/gui/app.py#L85-L178)）已采用 `QMainWindow + QDockWidget` 三栏骨架，方向正确，但需要做「视觉收口」：把顶部菜单精简、把状态栏信息结构化、把中央编辑器作为真正的视觉焦点。

### 1.2 功能区划分与导航体系

| 功能区 | 腾讯做法 | 设计要点 |
| --- | --- | --- |
| 顶部导航 | 极简菜单 + Tab 切换 | 高频入口靠肌肉记忆、低频入口下沉到设置 |
| 左侧导航 | 作品树 → 卷 → 章节 → 大纲节点 | 树状结构天然适合长篇层级 |
| 右侧辅助 | AI 助手 / 校对 / 知识库 / 朗读 | 默认折叠为可召唤的浮窗，按需出现 |
| 底部状态 | 字数 / 时长 / 自动保存 / AI 模型 | 不可关闭的「环境信息带」 |
| 全局命令 | 「搜索章节 / 跳转行 / 切换主题」等命令面板 | 高级用户的效率通道 |

**对 Continuum 的启发**：

- 当前侧边栏（[WorkSidebar](file:///d:/SynologyDrive1/Continuum/continuum/gui/views/sidebar.py)）已承载「作品 / 章节 / 大纲」三视图，但缺少折叠态、缺少搜索框、缺少快捷键指示；
- 底部「辅助工具」Dock 最大高度仅 140px（[app.py#L163](file:///d:/SynologyDrive1/Continuum/continuum/gui/app.py#L163)），是「旧功能收敛区」而非「创作辅助区」，需在 P1 阶段重新定位或下线；
- 缺少「命令面板」入口（VS Code / Obsidian 风格的 `Ctrl+K`），是高级用户效率提升的关键短板。

### 1.3 交互逻辑与状态反馈

腾讯写作助手在以下交互细节上做得较好：

1. **零干扰操作**：保存、字数刷新、模型切换均有状态指示，但不会弹窗打断；
2. **选区驱动的 AI**：选中正文 → 一键「润色 / 改写 / 续写」是写作流的核心动线；
3. **快捷键一致性**：`Ctrl+S / Ctrl+F / Ctrl+N / Ctrl+B/I` 等与桌面软件一致；
4. **空状态引导**：首次新建作品时给出「创建第一本书 · 导入文档 · 浏览示例」三选一；
5. **错误兜底**：API 失败、网络超时、配置缺失都有 Toast 提示而非崩溃弹窗；
6. **进度可见**：长任务（AI 生成、批量导入）有进度条与可取消按钮。

**对 Continuum 的启发**：当前 `_status_log` 走状态栏 6 秒短提示（[app.py#L502-L503](file:///d:/SynologyDrive1/Continuum/continuum/gui/app.py#L502-L503)）是合理的最小实现，但缺少 Toast 队列、全局错误中心、空状态引导模板，需要在 P1 系统化补齐。

### 1.4 视觉风格与品牌质感

| 维度 | 腾讯做法 | 行业共识 |
| --- | --- | --- |
| **字体** | 宋楷/思源宋体 类衬线作为正文主字体，配合无衬线 UI 字体 | 衬线字体强化「纸稿感」，无衬线保证 UI 清晰 |
| **配色** | 主色克制（蓝/绿单点高亮），大面积留白 | 写作工具应「低饱和 · 高留白」，避免色彩抢戏 |
| **图标** | 线性图标 + 双色填充（hover/激活态） | 线性图标更轻量；激活态必须明确 |
| **间距** | 8/12/16/24 px 节奏网格 | 网格化间距保证视觉一致性 |
| **圆角** | 6–8 px 卡片 / 4 px 按钮 | 圆角统一但不过分 |
| **阴影** | 极浅阴影 / 1px 边框为主 | 平面化减少视觉噪声 |

**对 Continuum 的启发**：[theme.py](file:///d:/SynologyDrive1/Continuum/continuum/gui/theme.py) 已实现亮/暗双主题，但缺少 Design Tokens（颜色、字号、间距、圆角的语义化变量），导致：

- 不同 view 各自硬编码颜色值；
- 新增视图难以保证视觉一致性；
- 主题切换时容易遗漏某些控件。

需要建立一套「Design Tokens → QSS 变量 → 控件实现」的三层链路。

### 1.5 响应式适配策略

腾讯写作助手为桌面端原生应用，策略是「**固定最小窗口 + 自适应内容**」：

- 最小窗口 1024×720，保证编辑区与侧栏不挤压；
- 窗口缩放时编辑区优先扩展，侧栏最小宽度保护（220–300 px）；
- Dock 可折叠、可隐藏、可堆叠；
- 关闭侧栏后窗口可缩至 800×600 的「极简码字」状态；
- 高 DPI 屏幕 1.25/1.5/2× 自适应缩放。

**对 Continuum 的启发**：[EditorPane](file:///d:/SynologyDrive1/Continuum/continuum/gui/views/editor_pane.py) 当前固定 `1280×820` 启动尺寸（[app.py#L61](file:///d:/SynologyDrive1/Continuum/continuum/gui/app.py#L61)），缺少：

- 最小窗口保护；
- 高 DPI 自适应策略；
- 窗口状态（位置/大小/Dock 折叠态）的恢复。

### 1.6 可复用经验与差异化优化方向

**可复用经验**（直接借鉴）：

1. 三栏式骨架（作品 · 编辑 · 助手）；
2. 编辑/双栏/预览三态切换；
3. 状态栏承载字数 · 模型 · 自动保存时间；
4. 选区驱动的 AI 润色/续写；
5. 衬线正文 + 无衬线 UI 的字体配比；
6. 8/12/16/24 px 节奏网格；
7. 暗色模式与护眼色温。

**差异化优化方向**（超越腾讯）：

1. **开源友好的视觉**：弱化平台 LOGO，强化内容本体（不抢戏、不绑平台）；
2. **AI 体验透明化**：模型切换、温度、Token 消耗、流式过程可视化（腾讯的 AI 行为对用户近乎黑盒）；
3. **沉浸模式升级**：在腾讯「极简码字」基础上，叠加番茄钟 / 强制码字 / 白噪音 / 字数目标进度环；
4. **可定制侧栏**：用户可拖拽组合「大纲 / 角色卡 / 世界观 / 伏笔 / 素材」面板（Scrivener 风格的拼装工作台）；
5. **命令面板 + 快捷键完全可配**：VS Code / Obsidian 级效率工具，腾讯助手未提供；
6. **跨端路线**：先桌面、后响应式 Web（QWebEngineView 内嵌）→ 后续移动端，原生体验不打折。

## 三、详细优化方案

### 3.1 视觉系统升级（Design Tokens + 主题引擎）

#### 3.1.1 Design Tokens 体系

建立四级 Token 结构：

```
Primitive Tokens（原子层）
  ↓ 语义映射
Semantic Tokens（语义层）
  ↓ 主题映射
Component Tokens（组件层）
  ↓ 控件实现
Qt QSS / Style Sheet
```

**Primitive Tokens（原子层）**

#### 3.1.3 字体策略

- **UI 字体**：Inter（拉丁）+ 苹方/微软雅黑（中文）双 fallback；

#### 3.3.2 关键交互节点设计

**A. 启动 · 空状态**

首次启动（无作品）：

- 中央编辑区呈现「欢迎卡片」：左 1/3 是品牌插画，右 2/3 是三张入口卡片：
  - 「📖 创建新作品」（主按钮）
  - 「📂 导入 Markdown / TXT」（次按钮）
  - 「🎓 浏览示例《雪山隐狐》」（次按钮，引导按钮）
- 侧栏顶部提示「还没有作品，点击下方新建」；
- 状态栏显示「续言 Continuum v1.0 · 数据本地 · 模型自选」。

非首次启动：恢复上次的作品 · 章节 · 编辑模式。

**B. 新建作品 · 向导式**

将 `QInputDialog` 单行输入升级为「新建作品向导」：

```
┌─ 新建作品 ────────────────────────────┐
│  作品名：________________________     │
│  副标题：______________________ (可选)│
│  题材： [玄幻 ▼]  类型：[长篇 ▼]      │

│  ┌─────────────────────────────┐    │
│  │                              │    │
│  └─────────────────────────────┘    │

```

向导数据写入 SQLite 的 `work` 表 + 默认章节模板。

**C. 码字 · 沉浸保护**

- 编辑区聚焦后，格式工具栏自动半透明，鼠标移出 3 秒后完全隐藏；
- 滚动条自动隐藏（仅滚动时短暂出现）；
- 字数变化有微妙动效（右上角数字 +N 的飞入动画，500 ms 淡出）；
- 目标进度条每 5 分钟更新一次（避免视觉疲劳）；
- 「保存」成功时标题栏的保存状态图标闪一下 ✓（不弹窗、不打断）。

**D. AI 辅助 · 选区驱动**

右栏 AI Tab 默认折叠为图标条（宽度 48 px）；按 `Ctrl+Shift+A` 或点击图标条展开为 360 px 宽抽屉。

**调用路径**：

| 触发方式 | 操作 | 反馈 |
| --- | --- | --- |
| 选中正文 → `Ctrl+R` | 润色 | 弹出微浮窗（diff 对比 / 整体替换二选一） |
| 选中正文 → `Ctrl+J` | 改写 | 同上 |
| 光标在行尾 → `Ctrl+Enter` | 续写 | 流式生成，结果以「淡灰底」预览，Tab 接受 / Esc 取消 |
| 选中正文 → 右键菜单 | 润色 / 改写 / 续写 / 翻译 / 总结 | 标准菜单 |
| 右栏 AI 对话 | 自由问答 | 流式显示，支持「插入到光标」「复制」「重新生成」「朗读」 |
| 右栏「知识库」Tab | 语义检索 | 卡片式结果，点击跳转到正文位置 |
| 右栏「校对」Tab | 全文校对 | 错误列表 + 原文高亮，一键应用修改 |

**AI 流式反馈规范**：

- 流式过程中按钮显示「生成中…」+ 旋转图标，可点击取消；
- 已生成内容即时显示在右栏，不阻塞编辑；
- 「插入到光标」前提供 10 行 diff 预览，避免误改；
- 失败时显示具体原因（401/网络/余额），并给出修复入口（跳转设置）。

**E. 校对 · 异常处理**

校对操作完成后：

- 成功：右栏展示问题列表（错别字 / 语病 / 敏感词 / 标点），每条带「原文 → 建议」对比，一键采纳/忽略；
- 部分失败：在通知中心记录成功条数与失败原因，提供「重试剩余项」；
- 全部失败：在通知中心高亮错误，提供「复制错误详情」与「打开日志」。

**F. 导出 · 多格式**

`Ctrl+Shift+E` 唤起导出向导：

- 格式：Markdown / HTML / PDF / EPUB / TXT；
- 范围：当前章节 / 当前卷 / 全书；
- 选项：是否包含大纲批注 / 是否包含 AI 摘要 / 是否水印；
- 输出路径：默认 `~/Documents/续言导出/<作品名>-<时间戳>.<ext>`。

导出过程中显示进度条与可取消按钮；完成在通知中心提示「已导出到 …，点击打开文件夹」。

#### 3.3.3 通知中心（Notification Center）

右上角铃铛按钮 + `Ctrl+Shift+N` 召唤：

- 抽屉式面板，按时间倒序展示通知；
- 分类：信息（蓝）/ 成功（绿）/ 警告（黄）/ 错误（红）；
- 每条支持「查看详情 / 复制 / 撤销操作（如适用）/ 清除」；
- 支持「勿扰模式」开关（沉浸模式下自动开启）。

#### 3.3.4 引导与帮助

- **首次使用引导（FTUE）**：3 步浮层引导「新建作品 → 写一段 → 让 AI 润色」；
- **场景化提示气泡**：每新增一项控件首次出现时显示气泡提示，3 秒后或用户操作后消失；
- **内置帮助中心**：`F1` 召唤 Markdown 渲染的帮助文档（含快捷键全图谱）；
- **快捷键速查卡**：`Ctrl+/` 召唤，分类展示所有快捷键，支持搜索与点击模拟。

  - 在光标位置以淡灰底插入预览文本

### 4.3 原型 · 评审 · 开发 · 测试流程要求

1. **原型制作**
   - 工具：Figma / Sketch（设计源）+ 截图标注；
   - 产物：高保真原型（含浅色 / 深色 / 护眼 三套），可点击流程；
   - 评审：产品 + 设计师 + 开发三方签字确认后方可进入开发。

2. **设计评审**
   - 检查项：Design Tokens 合规性、组件复用率（≥ 80%）、可访问性、响应式断点；
   - 输出：评审纪要 + 问题清单 + 修订计划。

3. **开发对接**
   - 设计资产交付：Figma 链接 + 切图（SVG 优先）+ 标注（颜色 / 字号 / 间距）；
   - 开发自测：开发完成后跑视觉回归（截图对比，差异 ≤ 2%）；
   - 提测前：填「UI 自测 checklist」。

4. **用户测试**
   - 招募 ≥ 5 名目标用户（含 1 名老年用户、1 名视障用户）做可用性测试；
   - 任务：新建作品 → 写 500 字 → 润色 → 导出，全流程录制；
   - 输出：可用性问题清单（Nielsen 启发式评估）+ NPS 评分。

5. **回归与发布**
   - 每两周一次小版本灰度；
   - 发布前：设计走查 Checklist（Design Tokens / 组件一致性 / 暗色 / 沉浸模式 / 无障碍）；
   - 发布后：监控用户反馈，48 小时内处理 P0/P1 视觉 Bug。
