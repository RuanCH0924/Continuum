## 2. 背景与目标

### 2.1 背景

网络文学长篇连载存在「写崩」「太监」高发问题，根源在于缺乏对故事整体框架的持续掌控。当前
Continuum 侧栏虽有「大纲」Tab，但仅承担「编辑器标题自动提取 + 跳转」的目录导航职能，不具备
**规划**能力——无法承载总纲、卷纲、章纲的搭建、节奏排布、角色成长曲线与篇幅管控。

参照腾讯作家助手「大纲设定（总纲 / 分卷大纲 / 章节细纲）+ 章纲提取」的产品逻辑，将大纲升级为
网文创作的核心规划工具，与编辑器、创作知识（角色/设定/伏笔/素材）、时间线共同构成完整的创作
数据闭环。

### 2.2 产品定位

> 大纲 = 故事的「施工图纸」：先搭骨架，再写血肉。

大纲模块是创作者在动笔前 / 连载中的规划层：支持从「仅梳理核心剧情节点」的粗纲，到「细化到
每一章具体内容」的细纲，两种粒度按需切换；并配套章纲管理、思维导图可视化、AI 智能提取与
大纲挂载问答四项辅助能力，降低规划成本、提升持续创作效率。

### 2.3 核心价值 → 需求映射

| 核心价值 | 支撑功能点 | 交付归属 |
| --- | --- | --- |
| ① 保障故事连贯性 | 总纲/卷纲节点结构化留存 + 章纲逐章承接 + 与伏笔/时间线数据同库可查 | 大纲工作台 + 章纲 |
| ② 规划故事节奏 | 大纲节点「节奏标签」（开篇/发展/高潮/转折/低谷/伏笔/结局）+ 章末钩子 | 大纲节点字段 |
| ③ 明确角色发展 | 大纲节点「涉及角色」关联角色卡 + 章纲「角色互动场景」 | 大纲节点 + 章纲 |
| ④ 管控故事篇幅 | 节点「预估字数」+ 卷纲聚合字数 + 与状态栏「今日字数/目标」形成进度参照 | 大纲节点字段 |
| ⑤ 提升创作效率 | 智能章纲提取（AI 生成）+ 大纲挂载问答（AI 答疑）+ 思维导图可视化 | AI 提取/问答 + 导图 |

| 节奏 / 篇幅管控 | 大纲方法：开篇→前期→中期→后期→结局，按卷细分字阶段 | 大纲节点节奏标签 + 预估字数（§6.3） |

## 4. 用户与场景

### 4.1 目标用户

| 用户类型 | 特征 | 核心诉求 |
| --- | --- | --- |
| 新人作者 | 无大纲写作经验，易写崩 | 模板化起步、低门槛的章纲填写引导 |
| 长篇连载作者 | 百万字量级，前文易遗忘 | 章纲提取回溯前文、总纲持续可查、问答辅助复习 |
| 细纲型作者 | 严谨规划，先纲后文 | 逐章章纲、角色互动与冲突点记录 |
| 灵感型作者 | 边写边想，粗纲为主 | 仅核心节点的大纲、思维导图快速可视化 |

### 4.2 典型场景

1. **开书规划（新人）**：新建作品后进入大纲工作台，按模板快速搭建「开篇→发展→高潮→结局」总纲节点，
   再为前 10 章填写章纲，随后回到正文写作。
2. **连载回溯（长篇作者）**：连载至 80 万字时，通过 AI「提取」选择「最近 20 章」，一键生成章纲，
   结合大纲节点快速找回前文剧情与伏笔状态。
3. **节奏排布（细纲作者）**：在大纲树中为各卷节点标记「高潮 / 低谷」节奏标签并填预估字数，
   直观查看全书篇幅分布，提前调整剧情密度。
4. **创作问答（所有人）**：选中大纲节点「北境风云」+ 指定章节「第 12 章 剑冢」，在 AI 问答中以
   「本书内容」为知识库来源提问「苏雪的出场是否与北境线冲突」，DeepSeek 结合引用内容流式回答。

## 5. 功能全景

```
大纲模块
├── A. 大纲主体（P0）
│   ├── A1 侧边栏「大纲」常驻入口 + 结构快捷导航
│   ├── A2 大纲工作台（中央模式：写作 ⇄ 大纲）
│   │   ├── A2.1 大纲列表视图（总纲/卷纲树 + 节点编辑）
│   │   ├── A2.2 粒度切换（仅核心节点 ⇄ 含逐章细纲）
│   │   └── A2.3 章纲视图（章纲列表 + 编辑卡片）
│   └── A3 大纲节点：节奏标签 / 预估字数 / 涉及角色 / 关联章节（跳转）
├── B. 章纲管理（P0）
│   ├── B1 每章一条章纲（核心剧情/角色互动场景/关键冲突点/章末钩子 + 自由备注）
│   └── B2 章纲状态（未写/写作中/已写）与提取标记
├── C. 思维导图（P1）
│   ├── C1 内置 SVG 导图编辑器（三种用途模板：剧情线/人物关系/世界观）
│   ├── C2 与大纲树双向生成（大纲→导图 / 导图→大纲）
│   └── C3 XMind 文本大纲导入（Tab/空格缩进 + Markdown 列表/标题）
├── D. 智能章纲提取（P1，AI「提取」）
│   ├── D1 范围：当前章节 / 最近 20 章 / 自定义（单批 ≤50 章）
│   ├── D2 配额：每成功提取 1 章消耗 1 次，每日 100 次，AI 功能全局共享
│   └── D3 结果自动写入章纲（覆盖需确认）
└── E. 大纲挂载智能问答（P1，AI「问答」）
    ├── E1 引用上下文：选中大纲节点 / 章纲 / 章节正文
    ├── E2 知识库来源「本书内容」（大纲+章纲+正文+创作知识）
    └── E3 DeepSeek 流式问答
```

优先级：P0 = 本轮必须交付；P1 = 与 P0 同批交付但可后置小项；模板中心/云端配额同步归 P2（§15）。

## 6. 大纲模块主体设计

### 6.1 功能入口与导航

**入口规则（对齐需求 1/2）**：

1. 侧边导航栏固定展示 7 个 Tab，**「大纲」Tab 保持常驻核心入口**（不折叠、不后置，位于「作品」之后）；
2. 点击「大纲」Tab → 中央区域由「写作模式」切换为「大纲模式」（大纲工作台），侧栏保持「大纲」Tab 高亮；
3. 大纲模式下侧栏内容区展示「大纲结构导航」：总纲/卷纲节点折叠树，点击节点 → 大纲工作台滚动定位并
   1.8s 临时高亮（复用伏笔/时间线联动信号模式）；
4. 返回写作：点击侧栏「作品」Tab / 任意章节 / 大纲工作台工具栏「返回写作」按钮，三路均可退出大纲模式；
5. 模式状态持久化于 `uiStore.centralMode`（不跨启动保留，默认回到写作模式）。

### 6.2 大纲工作台信息架构

| 视图 | 职责 | 内容 |
| --- | --- | --- |
| 大纲列表（默认） | 总纲 / 卷纲的结构化编辑 | 左侧大纲树 + 右侧节点详情/编辑；粒度切换控制树展开层级 |
| 章纲 | 逐章细纲管理 | 章节章纲卡片列表（§7） |
| 思维导图 | 可视化搭建 | SVG 导图画布（§8） |

**粒度切换**：
- 「仅核心节点」：大纲树只显示 `beat` 标签非空的剧情节点（开篇/高潮/转折/结局等关键节点），适合粗纲作者；
- 「完整细纲」：显示全部大纲节点 + 每章章纲入口（章节节点下内嵌章纲摘要），适合细纲作者。

### 6.3 大纲列表视图（总纲 / 卷纲树）

**树结构**：`总纲（根）→ 卷纲节点（kind=volume，可关联卷）→ 剧情节点（kind=story）`，节点可嵌套多层（剧情节点下可挂子剧情节点）。

**节点字段**（实体定义见 §6.6）：

| 字段 | 说明 | 示例 |
| --- | --- | --- |
| title | 节点标题 | 北境初雪 |
| content | 剧情梗概（Markdown） | 顾青舟于剑冢拔残剑，初遇苏雪 |
| beat | 节奏标签（开篇/发展/高潮/转折/低谷/伏笔/结局/其他） | 高潮 |
| targetWords | 预估字数（0=未填） | 50000 |
| volumeId? | 关联卷（可空） | vol_x |
| chapterSeqs? | 关联章节（点击跳转） | [3, 5] |
| characterIds? | 涉及角色（关联角色卡，展示卡名摘要） | [note_c1] |

**树交互规则**（遵循项目标准 S4 交互职责分离）：

| 操作 | 交互 | 说明 |
| --- | --- | --- |
| 展开/折叠 | 行首独立折叠图标按钮（stopPropagation，单击立即生效） | 与「双击重命名」按元素分离 |
| 重命名 | 双击行体（300ms 点击配对检测 + 原生 dblclick 兜底）→ 弹窗 | 同卷行/分组行逻辑 |
| 新建子节点 | 行内「＋」悬浮按钮 / 右键菜单 | 默认 type=story |
| 删除 | 右键 → 删除（二次确认；有子节点时提示「连同 N 个子节点一并删除」） | 级联清理 |
| 排序/调层级 | 右键上移/下移 + 拖拽落位（拖拽排序为增强项，P1） | order 归一化 |
| 关联章节 | 节点编辑面板选择章节（多选） | 点击节点「定位」→ 切换章节并跳转编辑器 |
| 跳转 | 点击节点标题 → 大纲工作台滚动定位并高亮 | 侧栏导航同源 |

**节点编辑**：右侧详情面板（标题 / 节奏标签 / 预估字数 / 关联章节 / 涉及角色 / 剧情梗概 Markdown 编辑区）。
编辑失焦自动保存（400ms 防抖，复用时间线内联保存模式），保存静默（状态栏「✓ 已保存」反馈，不弹窗）。

**空状态**：无大纲节点时显示引导卡：「还没有大纲，点击 [+ 新建节点] 搭建故事框架；或先创建章节，再通过
『生成骨架』按现有章节自动生成总纲草稿」。

### 6.6 数据模型定义（写入 `src/shared/types.ts`）

```ts
/** 大纲节点节奏标签（服务故事节奏规划） */
export type OutlineBeat =
  | 'opening'   // 开篇
  | 'rising'    // 发展
  | 'climax'    // 高潮
  | 'twist'     // 转折
  | 'lull'      // 低谷/铺垫
  | 'clue'      // 伏笔
  | 'ending'    // 结局
  | 'other'

/** 大纲树节点（总纲 / 卷纲 / 剧情节点，树形层级） */
export interface OutlineNode {
  id: string
  workId: string
  parentId: string | null        // null = 总纲根
  title: string
  /** 剧情梗概（Markdown） */
  content: string
  kind: 'story' | 'volume'       // 剧情节点 / 卷纲
  beat: OutlineBeat              // 节奏标签（other 时不展示色标）
  /** 预估字数（篇幅管控；0 = 未填） */
  targetWords: number
  /** 关联卷（可选） */
  volumeId?: string
  /** 关联章节（点击跳转编辑器） */
  chapterSeqs?: number[]
  /** 涉及角色（关联创作知识 character 卡片 id） */
  characterIds?: string[]
  /** 同级排序（升序） */
  order: number
  createdAt: number
  updatedAt: number
}

/** 章纲：每章一条，承载逐章细纲 */
export interface ChapterOutline {
  id: string
  workId: string
  chapterSeq: number
  /** 核心剧情 */
  corePlot: string
  /** 角色互动场景 */
  characterScenes: string
  /** 关键冲突点 */
  conflict: string
  /** 章末钩子（悬念，可选） */
  hook: string
  /** 自由备注（Markdown，可选） */
  content: string
  /** 是否由 AI 提取生成 */
  extracted: boolean
  /** 章节写作状态 */
  status: 'unwritten' | 'writing' | 'written'
  updatedAt: number
}

/** 思维导图节点（树） */
export interface MindMapNode {
  id: string
  text: string
  note?: string
  children: MindMapNode[]
}

/** 思维导图（一个作品一张总导图） */
export interface MindMap {
  workId: string
  root: MindMapNode
  updatedAt: number
}

/** AI 配额账本（每日 100 次，AI 功能全局共享）。 */
export interface AiQuota {
  /** 账本日期 YYYY-MM-DD；跨天懒重置 */
  date: string
  used: number
  budget: number      // 默认 100
}

/** 章纲提取请求 */
export interface OutlineExtractRequest {
  workId: string
  /** 提取的章节序号（有序、去重、≤50） */
  seqs: number[]
}

/** 章纲提取结果 */
export interface OutlineExtractResult {
  /** 成功写入章纲的章节 */
  success: number[]
  /** 失败章节及原因 */
  failed: { seq: number; reason: string }[]
  /** 实际消耗配额次数（= success.length） */
  quotaUsed: number
}
```

## 7. 章纲管理模块

### 7.1 定位

章纲是「总纲 → 卷纲 → 章纲」三级大纲的最细粒度，每章一条，明确记录该章核心剧情、角色互动场景、
关键冲突点与章末钩子，实现从全局规划到逐章执行的层级化管理（对齐需求 3.1）。

### 7.2 数据生成规则

- 章节创建时**不自动生成**章纲记录；首次填写 / AI 提取时按 `chapterSeq` upsert；
- 删除章节 → 级联删除对应章纲；
- 章节重命名不影响章纲（章纲以 `chapterSeq` 绑定）。

### 7.3 交互原型（章纲视图）

```
┌──────────────────────────────────────────────────────────────────┐
│ 章纲管理 · 共 12 章                          [仅显示未填写] [搜索…] │
│ ┌──────────────────────────────────────────────────────────────┐ │
│ │ 第 3 章 · 剑冢初遇        状态：[已写 ▼]     [定位正文] [问 AI] │ │
│ │ 核心剧情    顾青舟入剑冢，拔出残剑，初遇苏雪（内联编辑，失焦保存）│ │
│ │ 角色互动场景 顾青舟与苏雪初次交锋，互探虚实                      │ │
│ │ 关键冲突点  残剑认主引发宗门长老怀疑                            │ │
│ │ 章末钩子    残剑剑身浮现一行陌生文字                            │ │
│ │ 备注        （自由 Markdown，可展开）         来源：AI 提取 ✓   │ │

### 7.4 字段与交互规则

| 字段 | 控件 | 交互 |

## 8. 思维导图模块

### 8.1 定位

内置思维导图编辑工具，支撑三种创作可视化用途：**核心剧情线、人物关系网、世界观背景设定**；
支持导入 XMind 等外部工具导出的文本大纲，实现创作资料无缝迁移（对齐需求 3.2）。

### 8.2 数据与视图

- 数据独立存储（`mindmap.json` / SQLite `mind_maps` 表），一个作品一张总导图；
- 新建导图时提供三种预设根结构模板：**剧情线**（主线→开篇→发展→高潮→结局）、
  **人物关系**（核心人物→关系分支）、**世界观**（世界→地理→势力→力量体系），可自由增删改；
- 视图：SVG 树状图（右侧展开布局），支持缩放（滚轮）、平移（拖拽空白区）、自适应。

### 8.3 编辑交互

| 操作 | 交互 |
| --- | --- |
| 新建子节点 | 选中节点后 Tab / 行内「＋」 |
| 新建同级节点 | Enter |
| 编辑文本 | 双击节点（行内输入，Enter 确认 / Esc 取消） |
| 编辑备注 | 右键 → 编辑备注（弹窗，Markdown） |
| 删除 | Delete / 右键（二次确认，子节点级联删除） |
| 移动 | 拖拽节点到目标父节点（P1 增强） |
| 重命名/换色 | 右键菜单（颜色沿用 Design Tokens 语义色，P1） |

### 8.4 与大纲双向生成

| 方向 | 触发 | 规则 |
| --- | --- | --- |
| 大纲 → 导图 | 大纲工作台工具栏「生成导图」 | 以总纲为根，按树递归生成导图草稿（若已有导图则提示「覆盖 / 生成新根分支」）；仅文本快照，后续各自编辑 |
| 导图 → 大纲 | 导图工具栏「转为大纲」 | 选取根节点下所有分支 → 按层级递归创建大纲节点（kind=story），生成后进入大纲列表视图确认 |

> 设计决策：大纲树与导图**各自独立存储、单向快照生成**，避免双向实时同步的复杂度与数据竞态；
> 生成后两边各自演化，作者按需重新生成。

### 8.5 XMind 外部导入规范

**支持格式**（对齐 XMind 大纲导出与常见文本大纲）：

| 格式 | 示例 | 解析规则 |
| --- | --- | --- |
| Tab 缩进文本（XMind「大纲」导出） | `主线\n\t分支1\n\t\t子分支1\n\t分支2` | 每 Tab 一级；深度 = Tab 数 |
| 空格缩进（2/4 空格） | 同上 | 归一化：连续空格数 ÷ 最小缩进单位取整为深度 |
| Markdown 无序列表 | `- 主线\n  - 分支1\n    - 子分支1` | `-`/`*`/`+` 前缀；子项缩进 2/4 空格 |
| Markdown 标题 | `# 主线\n## 分支1\n### 子分支1` | 标题级别 = 深度 |

**导入流程与校验**：

1. 「+ 导入」→ 文件选择器（`.txt/.md`，读取全文）或粘贴文本框；
2. 解析为导图树：首个非空行 = 根；其余行按深度挂接；深度跳变 > 1 时自动修正（挂到最近可行父节点）并提示「已修正 N 处缩进」；
3. 导入前预览树形结果 → 确认导入（覆盖现有导图需二次确认）；
4. 导入失败（空文件 / 无层级）→ 明确错误提示，不落盘。

## 9. 智能章纲提取（AI · 提取）

### 9.1 功能入口

右侧 AI 面板 Tab 由 4 个扩展为 5 个：**对话 / 润色 / 续写 / 知识库 / 提取**（「提取」为新增分类，
图标 `sparkle` 变体或 `doc`）。不占用大纲工作台空间，遵循「AI 能力集中」的产品一致性。

### 9.2 提取范围规则（对齐需求 3.3）

| 范围选项 | 计算规则 | 边界 |
| --- | --- | --- |
| 当前章节 | 当前打开章节 | 仅 1 章 |
| 最近 20 章 | 当前章节起向前 20 章（含当前） | 不足 20 章按实际 |
| 自定义范围 | 章节树勾选（默认按卷分组） | **单批 ≤ 50 章**，超出时禁止提交并提示「单批最多 50 章，请分批提取」 |

**预检规则**（提交前主进程统一校验，返回拒绝原因）：

| 校验项 | 规则 |
| --- | --- |
| 章节有效性 | 所选章节均存在且正文非空（字数 ≥ 100，否则跳过并计入提示） |
| 配额充足 | 剩余配额 ≥ 待提取章数；不足时提示「配额不足，今日剩余 X 次」 |
| AI 配置 | 已配置有效 AI（本地 Ollama 免 Key 除外）；未配置阻断并引导设置 |

### 9.3 交互流程（线框）

```
┌──────────────────────────────────────────────────────────┐
│ AI · [对话][润色][续写][知识库][提取]                     │
│ ┌──────────────────────────────────────────────────────┐ │
│ │ 智能章纲提取                                           │ │
│ │ 提取范围： (●) 当前章节   ( ) 最近 20 章   ( ) 自定义范围 │ │
│ │ 自定义：  [展开章节勾选列表 · 按卷分组 · ≤50]            │ │
│ │ ─────────────────────────────────────────────────── │ │
│ │ 本次将提取 12 章 → 消耗配额 12 次                       │ │
│ │ 今日剩余配额：88 / 100        [开始提取]                │ │
│ │ ─────────────────────────────────────────────────── │ │
│ │ 提取进度： 3 / 12  ▓▓▓░░░░░░░░░  [取消]                │ │
│ │ 当前：第 9 章《剑冢初遇》…                              │ │
│ │ 完成：成功 12 · 失败 0 · 跳过 0 · 剩余 0                │ │
│ │ 结果已写入章纲 → [去大纲工作台查看]                      │ │
│ └──────────────────────────────────────────────────────┘ │
└──────────────────────────────────────────────────────────┘
```

**交互要点**：

1. 勾选范围后实时显示「将提取 N 章 → 消耗配额 N 次」；
2. 开始后逐章排队处理（并发 1），进度条 + 当前章节名 + 可取消（已完成的章节保留，不重复扣配额）；
3. 完成后 Toast 汇总 + 通知中心回执（成功/失败/跳过明细，可「复制详情」）；
4. 结果自动写入对应章纲（未创建则创建，`extracted=true`）；目标章纲**已有手写内容**时弹确认：
   「将覆盖第 N 章手写章纲（推荐先备份）」，提供「追加到备注 / 取消」选项（默认追加，避免误覆盖）；
5. 「去大纲工作台查看」→ 切换中央模式并定位章纲视图对应章节。

### 9.4 配额规则（对齐需求 3.3）

| 规则项 | 约定 |
| --- | --- |
| 计费粒度 | **每成功提取 1 章 = 消耗 1 次**；失败、跳过、取消均不消耗 |
| 每日额度 | 100 次/日，账本 `settings.aiQuota`（date/used/budget） |
| 重置 | 跨天懒重置：读取时 `date ≠ 今日` → `used = 0` 并更新日期 |
| 共享 | AI 模块**全局统一账本**（含 Web 端）；当前仅「提取」实际消耗，问答/润色/续写/知识库暂免费但共用同一账本结构（`consumers` 计费策略预留，见 §10.2） |
| 并发安全 | 扣减在主进程原子完成（同一时刻仅一个提取任务），渲染层只读展示 |
| 跨端 | 桌面端本地账本；Web 端复用同一语义（服务端账本），全端共享待账号体系接入（P2） |

### 9.5 调用逻辑（时序）

```
渲染层 ExtractTab                      主进程 extract-service               AiQuotaService         openaiCompat(DeepSeek)
   │ 1. quota:get ────────────────► 读取账本（懒重置）→ 返回 {used,budget}
   │ 2. 选择范围 → 组装 seqs（≤50）
   │ 3. chapter-outlines:extract(workId,seqs)
   │ ◄─────────────────────────── 预检：章节有效 / 配额≥N / AI 配置
   │                             （不满足→拒绝 {code,message}，无副作用）
   │ 4. ── 预占配额 N（used+N，余额不足回滚）──►
   │ 5. 逐章（并发 1）：
   │     读正文 → 截断(≤8000字) → 组提示词 ──► chat/completions(stream=false)
   │     解析 JSON 章纲 → 字段校验
   │     空章节(<100字)→跳过(回滚1)；解析失败→重试1次→仍失败(回滚1,记原因)
   │     成功 → 写入 chapter_outlines.json（覆盖需经渲染层确认，默认追加）
   │     每章完成 → quota.commit(1)（used 递减回滚逻辑反走）
   │     progress 事件推送（IPC: chapter-outlines:extract-progress）
   │ 6. 返回 OutlineExtractResult
   │ ◄──────────── Toast 汇总 + 通知中心回执
```

**提示词模板（提取）**：

```
你是一名资深网文编辑。请根据给定章节正文提取该章章纲，输出严格 JSON（不要输出任何多余文字）：
{"corePlot":"本章核心剧情（≤120字）","characterScenes":"本章角色互动场景（≤120字）",
 "conflict":"本章关键冲突点（≤80字）","hook":"章末钩子/悬念（≤60字，无则空字符串）"}

章节正文（已截断）：
...
```

**容错**：网络/流中断 → 该章重试 1 次；DeepSeek 超时/限流（429）→ 记录原因，批量任务继续下一章，
汇总结果中标注失败明细与建议（重试/检查配置）。

## 10. 大纲挂载智能问答（AI · 问答）

### 10.1 功能入口与交互

在 AI「对话」Tab（问答）增强，全端可用（桌面端本期落地，Web 端架构预留 §10.5）。新增能力：

1. **引用上下文选择器**（输入区上方）：
   - 「📎 引用」按钮 → 选择器弹层：大纲节点 / 章纲 / 章节正文（按卷分组勾选，可多选）；

   - 大纲工作台 / 章纲卡片内「问 AI」按钮 → 一键带入对应节点并聚焦问答输入框；
2. **知识库来源下拉**（对齐需求 3.4 的「本书内容」）：
   - `注入知识库（RAG 检索）`：维持现有逻辑——检索命中片段注入（默认开）；
   - `本书内容（大纲+章纲+正文+创作知识）`：**显式引用内容直接注入**（非仅检索片段）；
   - 两者可叠加：勾选「本书内容」时以引用内容为主，检索片段为辅；
3. 发送后调用 DeepSeek 流式问答（复用 `openaiCompat` 适配层，Provider 默认 DeepSeek，可在设置切换），
   回答进入现有对话流（支持插入光标/复制/重新生成）。

**线框**：

```
│ 对话流（现有气泡，流式渲染）                                  │
│ ──────────────────────────────────────────────              │
│ [📎 引用…] 知识库来源：〔本书内容 ▼〕                          │
│ 📎 大纲《北境初雪》 ×   📎 第12章《剑冢初遇》 ×                │
│ [输入创作问题…]                                 [发送]        │
```

### 10.2 「本书内容」知识库组装逻辑

| 步骤 | 规则 |
| --- | --- |
| 收集 | 显式引用（大纲节点 content + 章纲四字段 + 章节正文）全量收集；未显式引用时按当前作品全量大纲/章纲 + 检索命中正文片段 |
| 裁剪 | 按「章节正文 → 章纲 → 大纲 → 创作知识」优先级拼装，截断至 **6000 字**窗口（超出截尾，过长章节取首尾各半） |
| 注入 | 追加至系统提示词：`【本书内容参考（回答创作问题时可参考，不必逐条引用）】\n- [大纲] 北境初雪：…\n- [章纲] 第12章：核心剧情…冲突…\n- [章节] 第12章：…` |
| 透明化 | 沿用「透明 AI」徽标，展示「已注入上下文：本书内容（大纲 ×1 · 章纲 ×1 · 章节 ×1）」 |
| 降级 | 收集失败/为空 → 自动退回 RAG 检索注入，不阻塞 |

### 10.3 调用逻辑

```
渲染层 对话 Tab                      aiStore                       openaiCompat(DeepSeek)
 1. 选择引用（大纲/章纲/章节）→ 胶囊列表
 2. 知识库来源 = 本书内容
 3. sendChat(question, withContext, withKnowledge, scope=本书内容)
    ──► 组装【本书内容参考】→ 并入系统提示词 ──► chat/completions(stream)
    ◄── SSE 增量 → 流式渲染 → 完成/中止
 4. 错误分层沿用现有 AIError 体系（缺Key/401/429/网络）→ 气泡内原因 + 操作行
```

listOutlineNodes(workId: string): OutlineNode[]
saveOutlineNode(workId: string, node: OutlineNode): OutlineNode        // upsert
deleteOutlineNode(workId: string, id: string): boolean                 // 级联删子节点
reorderOutlineNodes(workId: string, parentId: string | null, orderedIds: string[]): boolean
listChapterOutlines(workId: string): ChapterOutline[]
saveChapterOutline(workId: string, outline: ChapterOutline): ChapterOutline
deleteChapterOutline(workId: string, chapterSeq: number): boolean
getMindMap(workId: string): MindMap | null
saveMindMap(workId: string, map: MindMap): MindMap
// 级联：deleteChapter → 删对应章纲；deleteWork → 删 outline/chapter_outlines/mindmap 文件
```

**配额账本**：`settings.json` 的 `aiQuota` 键（`{date, used, budget}`），主进程 `AiQuotaService`（新文件
`services/quota.ts`）提供 `get/check/occupy/commit`，懒重置 + 原子扣减。

### 12.4 依赖与性能

- **零新运行时依赖**（对齐项目「零原生依赖」原则）：思维导图自实现 SVG，不引入 d3/mermaid；
- 提取服务在主进程排队执行（并发 1），避免多章并发打爆额度与限流；
- 大纲树/章纲数据量级小（万级节点内），全量加载 + 内存操作足够，无需分页；
- 正文注入裁剪 6000 字窗口，控制每次请求 Token 成本。

### 12.5 Web 端复用预留

- 交互与逻辑（范围选择、引用组装、注入拼装、导图解析）抽离为**渲染层 lib**（`lib/outline/*`、
  `lib/mindmap.ts`、`lib/extractScope.ts`、`lib/chatScope.ts`），Web 端直接复用；
- 存储与配额：Web 端替换为服务端 API（同一 IPC 契约语义），`AiQuotaService` 语义共享，跨端账本
  待账号体系接入后同步（P2）。
